# הוצאות — Expenses PWA

אפליקציית Web מתקינה (PWA) לניהול הוצאות יומיומיות, בנויה למסך של אייפון ולהזנה ביד אחת.
הנתונים נשמרים מקומית במכשיר ב-IndexedDB, והאפליקציה עובדת גם ללא אינטרנט לאחר הטעינה הראשונה.

ממשק באנגלית כברירת מחדל, עם מעבר לעברית (RTL מלא) ב-**Data and settings**.

---

## הרצה מקומית

דרישות: Node.js 20 ומעלה (נבדק על Node 24).

```bash
npm install
npm run dev          # http://localhost:5173
```

| פקודה | מה היא עושה |
|---|---|
| `npm run dev` | שרת פיתוח |
| `npm run dev:host` | שרת פיתוח חשוף לרשת המקומית, לבדיקה מהנייד |
| `npm run build` | בנייה לפרודקשן + יצירת Service Worker |
| `npm run preview` | הרצת ה-build המקומי (http://localhost:4173) |
| `npm run test` | כל הבדיקות (Vitest + React Testing Library) |
| `npm run test:watch` | בדיקות במצב watch |
| `npm run generate-pwa-assets` | יצירת כל אייקוני ה-PWA מ-`public/favicon.svg` |

### בדיקה מהאייפון ברשת הביתית

```bash
npm run build
npm run preview:host
```

ואז לפתוח בסאפארי את הכתובת שמוצגת תחת `Network` (למשל `http://192.168.1.20:4173`).

> כך אפשר לבדוק את הפריסה והמגע, אבל **לא** את ההתקנה למסך הבית ולא את העבודה ללא אינטרנט:
> Service Worker דורש HTTPS. לשם כך צריך לפרוס — ראה בהמשך.

## פריסה ל-Vercel

הפריסה נדרשת כדי להתקין את האפליקציה באייפון: סאפארי מאפשר הוספה למסך הבית ושמירה אופליין
רק מאתר שמוגש ב-HTTPS.

```bash
npm install -g vercel     # פעם אחת
vercel login
vercel --prod
```

`vercel.json` כבר מוגדר בפרויקט (build, תיקיית `dist`, ניתוב SPA וכותרות cache).
בסיום הפקודה תתקבל כתובת `https://<שם-הפרויקט>.vercel.app`.

חלופה: Netlify (`npx netlify deploy --prod --dir=dist` לאחר `npm run build`), או כל אירוח סטטי
עם HTTPS שמגיש את תוכן `dist/`.

## התקנה באייפון

1. לפרוס את האפליקציה ולקבל כתובת HTTPS (ראה למעלה).
2. לפתוח את הכתובת **בסאפארי** באייפון — לא בכרום ולא מתוך אפליקציה אחרת.
3. ללחוץ על כפתור **שיתוף** (הריבוע עם החץ כלפי מעלה) בתחתית המסך.
4. לגלול ולבחור **"הוספה למסך הבית" / "Add to Home Screen"**.
5. לאשר. האייקון יופיע במסך הבית בשם **הוצאות**.

לאחר ההתקנה האפליקציה נפתחת במסך מלא, ללא שורת הכתובת של סאפארי, ועובדת גם במצב טיסה.

## שימוש

### הוספת הוצאה

הטופס נמצא בראש המסך כדי שלא יידרש גלילה:

- **Amount + Currency** — סכום ומטבע. ברירת המחדל ₪ (ILS), וגם € (EUR) ו-$ (USD).
  המטבע האחרון שנבחר נשמר להוספה הבאה. באייפון נפתחת מקלדת מספרית.
- **Store / place** — שם החנות או המקום. **שדה חובה.** עם השלמה אוטומטית מחנויות קודמות.
- **Description (optional)** — פירוט חופשי. לא חובה. גם כאן יש השלמה אוטומטית.
- **Payment method** — Cash (ברירת מחדל) או Credit.
  בבחירת Credit נפתחים שני שדות: **Card** — ארבע הספרות האחרונות של הכרטיס, **שדה חובה**
  — ו-**Installments** (1 עד 36). בשני תשלומים ומעלה מוצג סכום התשלום המשוער.
  בפעם הראשונה שדה הכרטיס הוא שדה הקלדה ריק. מרגע שנשמר כרטיס אחד, השדה הופך לרשימה
  נפתחת עם **כל** הכרטיסים שהוזנו — האחרון שבשימוש כברירת מחדל — ועם אופציית
  **+ New card…** להוספת כרטיס נוסף.
- **Add** — שומר, מציג הודעת הצלחה, מנקה את הסכום והטקסט, ומחזיר את אמצעי התשלום ל-Cash.
  לחיצה כפולה לא תיצור שתי הוצאות. תאריך ושעה נחתמים אוטומטית לפי השעון המקומי.

### רשימה, חיפוש וסיכומים

הרשימה מוצגת מהחדש לישן, עם עריכה ומחיקה (עם אישור) בכל שורה.
**Search and filter** מאפשר חיפוש בשם החנות ובפירוט, סינון לפי טווח תאריכים, מטבע ואמצעי תשלום,
ומיון לפי תאריך או סכום.

הסיכומים מוצגים **בנפרד לכל מטבע** — היום, החודש, מזומן, אשראי וסך הכל.
אין המרת מטבע, ולכן סכומים ב-₪, € ו-$ לעולם אינם מחוברים לסכום אחד.

### ייצוא וגיבוי

ב-**Data and settings**:

- **Export to CSV** — נפתח חלון שבו בוחרים קודם טווח תאריכים ואמצעי תשלום (או "All"),
  ורק אז נוצר הקובץ. הקובץ נכתב ב-UTF-8 עם BOM כדי שעברית תיקרא נכון באקסל.
- **Back up to JSON** — גיבוי מלא של כל ההוצאות.
- **Restore from JSON** — שחזור מקובץ גיבוי. דורש אישור מפורש, כי הוא **מוחק ומחליף** את כל הנתונים.

> **הנתונים נשמרים במכשיר בלבד.** זהו אינו גיבוי בענן. מחיקת נתוני האתר, גלישה במצב פרטי
> או מעבר למכשיר אחר יגרמו לאובדן הגישה אליהם. כדאי לייצא גיבוי JSON מדי פעם.

```
│  ├─ money.ts             פענוח ועיצוב סכומים, חישוב תשלומים
│  ├─ validation.ts        ולידציית הטופס ובדיקת רשומות משוחזרות
│  ├─ summaries.ts         סיכומים לפי מטבע
│  ├─ filters.ts           חיפוש, סינון, מיון והשלמה אוטומטית
│  ├─ datetime.ts          ISO מקומי ועיצוב תאריכים
│  └─ backup.ts            CSV, גיבוי ושחזור JSON
├─ data/
│  ├─ db.ts                סכמת IndexedDB ומיגרציות
│  ├─ ExpenseRepository.ts הממשק שכל האפליקציה עובדת מולו
│  ├─ idbExpenseRepository.ts  המימוש המקומי
│  └─ preferences.ts       שפה, מטבע אחרון (localStorage)
├─ hooks/                  useExpenses, useToast
├─ i18n/                   מילוני he/en ו-I18nProvider
└─ components/             הטופס, הרשימה, הסינון, הסיכומים והדיאלוגים
```

### מודל הנתונים

```ts
interface Expense {
  id: string
  amountMinor: number      // מספר שלם באגורות/סנטים
  currency: 'ILS' | 'EUR' | 'USD'
  merchant: string         // חובה
  description?: string     // אופציונלי
  paymentMethod: 'cash' | 'credit'
  cardLast4?: string       // רק באשראי
  installmentsCount: number
  dateTime: string         // ISO עם אופסט מקומי
  createdAt: string
  updatedAt: string
  syncStatus: SyncStatus   // הכנה ל-Backend
  serverId?: string        // הכנה ל-Backend
}
```

הסכום נשמר כמספר שלם ביחידות משנה (`amountMinor`) ולא כמספר עשרוני, כדי שחיבור סיכומים
לא יצבור שגיאות נקודה צפה.

מספר התשלומים נשמר יחד עם הסכום המקורי בלבד — האפליקציה **אינה** יוצרת חיובים חודשיים עתידיים.
סכום התשלום המשוער מחושב לתצוגה בלבד. לעולם לא נשמרים מספר כרטיס מלא, CVV או פרטי תשלום רגישים.

## הוספת Backend ב-C# בעתיד

כל גישה לנתונים עוברת דרך `ExpenseRepository` ב-[src/data/ExpenseRepository.ts](src/data/ExpenseRepository.ts).
כדי לחבר שרת, מוסיפים מימוש נוסף (למשל `ApiExpenseRepository`) מול ה-API, ומחליפים את המופע
ב-[src/App.tsx](src/App.tsx). הקומפוננטות עצמן אינן משתנות.

השדות `syncStatus` ו-`serverId` כבר קיימים במודל, כך שסנכרון לא ידרוש מיגרציית סכמה של המודל עצמו.
